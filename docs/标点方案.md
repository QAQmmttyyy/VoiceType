# 标点方案

## 结论

标点由 **SenseVoice 在识别时一并产出**，不挂任何独立的标点模型。

## 历史：为什么曾经挂过 Qwen2.5-0.5B

早期实现里，SenseVoice 之后接了一环「本地 LLM 加标点」，用 Qwen2.5-0.5B-Instruct，
并配了一层字符级保真校验：把标点全部剔除后逐字比对，字符有任何增删改就丢弃这次输出。

想法是合理的，但实测下来这套组合的投入产出为负。

## 实测数据

测试语料：65 条互不重复的完整句子，长度 18~711 字，覆盖纯中文 / 纯英文 / 中英混说。
环境：M2 / MPS。

### 保真校验的通过率

| 分组 | 通过率 |
| --- | --- |
| 纯中文 | 47.5% (19/40) |
| 中英混说 | 10.0% (1/10) |
| 纯英文 | **0.0%** (0/10) |
| 长文本 | 20.0% (1/5) |

**整体 32.3% 通过，67.7% 被丢弃。**

被丢弃时，代码回退到 SenseVoice 的原文——而原文**本来就带标点**，
所以用户看到的其实一直是 SenseVoice 的标点，Qwen 那 67.7% 的工作等于白跑。

### 它到底改了什么

英文：**直接翻译成中文**。

```
we need to finalize the pricing before the launch next month
→ 我们将在下个月完成定价。
```

中英混说：**把英文词换成中文**。

```
这个 feature 下周三之前必须 merge 掉
→ 这个功能在下周三之前必须合并掉
   feature→功能   merge→合并

你把这个月的 revenue 报表 export 成 PDF 发我
→ 你把这个月的收入报表导出成PDF给我
   revenue→收入   export→导出
```

纯中文：**按书面语润色**。

```
开个会 → 召开会议        反馈说 → 反馈：
这周 → 本周              后来 → 后来又
```

这是 instruct 模型的本能。prompt 用中文写、模型又偏中文，
它把任务理解成「把这段话说得规范些」，靠改 prompt 压不住。

### 保真校验本身的漏洞

```python
strip = lambda s: re.sub(r"[，。！？、：；,.!?;: ]", "", s)
#                                              ↑ 空格也被剔除了
```

因为空格被归一化掉，模型**插入任意空格也能通过校验**，产出：

```
明天上午 10 点之前 把 初稿 发到 群里 。
这个 feature 下周三之前 必须 merge掉 。
```

也就是说，它能「通过」的那 32.3% 里，有一部分是这类被污染的文本。

### 输出上限写死的问题

原先 `max_new_tokens` 固定 180。中文约 1 字 1 token，
输入超过约 300 字时生成被截断，保真校验随即失败、标点整段丢失。

改成按输入长度动态计算后，触顶样本从 4 条降到 0 条。
（但这不是拒绝率的主因，拒绝率的根因是上面那三条。）

## SenseVoice 自带的标点够用吗

够用。同样语料，不带任何后处理：

```
今天下午3点，我们开个会讨论下个季度的产品规划。
客户反馈说，登录页面在浏览器上打开有点慢。
麻烦你把这个月的报销单整理一下，发给我。
他说，这个功能要先跟设计确认一下再开发。
```

疑问句、短句、长句都对：

```
这个方案你觉得可行吗？                 ← 问号正确
你什么时候能把文档发给我？
好的。   收到。   明天见。

我看了下这个季度的数据增长比预期要好。但是如果按照目前的趋势，
下个季度可能会放缓，所以我们可能需要提前准备一些应对方案。
```

标点密度比 LLM 略稀（较少插入描述性逗号），但**停顿位置正确，且物理上不可能改写或翻译**。

## 移除后的收益

| 项 | 变化 |
| --- | --- |
| 模型下载量 | 1.8 GB → 897 MB |
| 首装总下载 | 约 3 GB → 约 2.1 GB |
| 单次标点耗时 | 中位 436 ms → 0（长文本最长 18.5 s → 0） |
| 训练/推理依赖 | 少一个 953 MB 的 LLM |

## 如果将来需要更密的标点

funasr 自带 `ct_transformer`（Controllable Time-delay Transformer）实现，
可加载 ModelScope 上的专用标点模型（如 `punc_ct-transformer_cn-en-*`）。

相比 LLM 的关键差异是**架构**：它是**逐位置分类**，输出空间里只有「这里插不插标点」，
**没有替换字符这个选项**，所以不存在翻译/改写的可能，也就不需要保真校验。
代价是它有自己的最大输入长度，超长文本要按句切块。

目前的效果看，没必要上。
